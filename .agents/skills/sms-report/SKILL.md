# Квартальный отчёт СМС

1. Прочитай `AGENTS.md`, журнал, историю планов и README отчётного квартала. Подтверди выбранный период по контексту пользователя.
2. Используй свежую доступную выгрузку. База пользовательского localhost не равна данным репозитория. При её недоступности явно укажи, какая версия использована.
3. Включай только выбранные неархивные мероприятия квартала в порядке `report_order`. Не переноси старые факты, числа и фото вместе с оформлением.
4. Основной механизм сборки — `webapp/report_builder.py`: `build(snapshot, output_directory)`. Снимок создаётся `Journal.report_snapshot(quarter)` в `webapp/server.py`. Для репозиторных данных используй временный Journal, не создавай рабочую `.data` ради проверки.
5. Применяй сохранённый PPTX III квартала как шаблон для нового периода. Сохраняй 16:9, Verdana, цвета, логотипы, изогнутую границу и расположение блоков. Для неизвестных чисел оставляй прочерки.
6. Видимая численность — только число и форма слова «человек». Скобки, формулы и пояснения остаются в журнале и заметках, но не рядом с числом на слайде.
7. Для фото используй `sms-photos`, для завершающего слайда — `sms-planning`. После IV квартала следующий период — I квартал следующего года.
8. Перед сборкой проверь окружение командой `python tools/check_tools.py`. Для PDF нужен PowerPoint в Windows либо LibreOffice. Установленный python-pptx сам не экспортирует PDF.
9. Сначала собирай оба файла во временный каталог. Применяй `sms-review`; предыдущую рабочую пару заменяй только после успешной проверки новой.
10. При обновлении репозитория сохраняй существующие имена файлов, обнови журнал и README. Для сайта готовые версии хранятся в `.data/reports`; публикация через GitHub Pages — отдельный шаг.

Результат: редактируемый PPTX и соответствующий PDF, краткое описание состава и недостающих данных. Не объявляй отчёт обновлённым после одного изменения JSON.
