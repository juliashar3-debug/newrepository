# Журнал мероприятий СМС

Сайт для ведения журнала Совета молодых специалистов АО ЦКБА. Требуется Python 3.12 или новее. Устанавливать зависимости не нужно.

Из корня репозитория:

```bash
python3 event-journal/server.py
```

Откройте http://127.0.0.1:8000 на том же компьютере. Для удалённой среды нужен настроенный доступ к порту; адрес loopback удалённой машины не открывается на другом устройстве.

## Возможности

- Список существующих мероприятий, поиск, выбор квартала и статуса.
- Создание и редактирование: название, даты, квартал, место, организатор, описание, эффект, участники СМС, общий охват, источники чисел, примечания, включение в отчёт.
- До шести новых JPEG/PNG/WebP за одно сохранение, не более 8 МБ каждый. Оригиналы не сжимаются. Сохранённые фото доступны в карточке мероприятия.
- Неизвестные числа остаются `null`, а не нулём. Квартал проверяется по дате; численность и источники валидируются на сервере.
- Экспорт полного журнала JSON.

## Хранение

Сервер читает и атомарно обновляет `presentations/events.json`, сохраняя дополнительные поля существующих записей. Фотографии записываются в `presentations/YYYY-QN/photos/<id>/`. PPTX, PDF, планы и существующие оригиналы не изменяются. Сохранение через сайт меняет файлы на диске, но не создаёт Git-коммит и не отправляет данные в GitHub автоматически. После работы сохраните изменения в Git обычным способом.

Запускайте один процесс сервера для этого репозитория; не редактируйте `events.json` одновременно с сохранением через сайт. Перед операциями с общим журналом рекомендуется резервная копия/Git-коммит.

По умолчанию сервер слушает только `127.0.0.1`. Для контролируемого размещения за шлюзом с аутентификацией можно указать `--host 0.0.0.0 --port 8000`. Собственной авторизации в приложении нет: не открывайте его напрямую в публичный интернет. Постоянный хостинг Sites не настроен: в текущей среде отсутствуют служебные скрипты Sites. Для публикации потребуется поддерживаемая среда Sites с серверным хранилищем либо сервер с постоянным диском и закрытым доступом.

## Проверка

```bash
python3 -m unittest discover -s event-journal -p 'test_*.py' -v
node --check event-journal/static/app.js
```

Тесты используют отдельную временную копию журнала и не изменяют рабочие данные.
