# Полный журнал на GitHub Pages

Сайт: https://juliashar3-debug.github.io/newrepository/site/

Доступны просмотр мероприятий и фото, добавление, редактирование, архивирование и восстановление, выгрузка JSON/ZIP, создание и обновление PPTX/PDF за любой квартал. Сборка использует оформление сохранённого III квартала; IV квартал заканчивается предложениями на I квартал следующего года.

## Подключение владельца

Посетители могут смотреть журнал и скачивать отчёты. Для изменения карточек нажмите **«Подключить владельца»**. В диалоге есть ссылка на создание fine-grained personal access token в GitHub. Выберите владельца `juliashar3-debug`, только репозиторий `newrepository`, права **Contents: Read and write** и **Actions: Read-only**. Вставьте ключ в поле на сайте. Не отправляйте его агенту или в чат.

Ключ отправляется только `api.github.com`, хранится в памяти вкладки и очищается при отключении или перезагрузке. В localStorage, sessionStorage, Git, выгрузки и адреса страниц ключ не записывается. Проверяется аккаунт владельца; сам доступ на запись дополнительно проверяет GitHub. Сайт не содержит встроенного общего ключа. После закрытия/перезагрузки вкладки подключение нужно повторить.

Данные и оригиналы фотографий находятся в **открытом репозитории**: заметки, формулы, архивные и исключённые карточки также доступны через исходные файлы. Подключение владельца ограничивает запись, а не видимость этих материалов.

## Сохранение и отчёты

- `presentations/online-journal.json` — текущие карточки онлайн-журнала. Фото сохраняются в `presentations/online-uploads/`; исходные фотографии III квартала остаются на прежних местах.
- Сведения, набор фотографий и выбранный общий снимок сохраняются одним Git-коммитом. При одновременном изменении ветки сайт сохраняет несохранённую форму и предлагает открыть актуальную карточку; чужие изменения не перезаписываются.
- «Сформировать»/«Обновить» записывает запрос в `presentations/report-request.json`. Workflow **Build SMS report** создаёт PPTX и PDF в GitHub Actions через Python и LibreOffice. PowerPoint на компьютере посетителя не требуется.
- Новая пара появляется только после успешного экспорта и проверки количества страниц. Workflow сохраняет оба файла и `presentations/online-reports.json` одним коммитом. При ошибке прежняя пара остаётся доступной. Изменения карточек во время сборки сохраняются и вызывают предложение обновить отчёт ещё раз.
- Страница получает актуальные карточки и ссылки на отчёты непосредственно из GitHub. После успешной сборки скачивание новой пары не зависит от повторного развёртывания Pages. Если закрыли вкладку во время сборки, откройте её снова через несколько минут; результат также доступен в Actions → Build SMS report.
- LibreOffice на сервере использует доступные шрифты. PPTX сохраняет заданный Verdana; если его нет на сервере, в PDF используется системная замена. Для точного совпадения метрик шрифта можно экспортировать PPTX установленным PowerPoint с Verdana.

Локальный журнал `127.0.0.1:8765` и его `.data` остаются отдельными. Онлайн-сохранение не переносит несинхронизированные изменения с компьютера. Для переноса передайте актуальную выгрузку и фото агенту. Не заменяйте локальную `.data` данными репозитория.

## Публикация и обслуживание

Поддерживаются оба источника Pages: **Deploy from a branch → main → /(root)** и **GitHub Actions**. Корневой `index.html` открывает `site/`. Workflow `Publish SMS journal` собирает ту же структуру. При обновлении интерфейса обновляйте и исходники, и сгенерированный каталог `site/`, чтобы публикация из ветки показывала новую версию.

```sh
python -m pip install -r webapp/requirements.txt
python tools/build_public_site.py --output /tmp/sms-site-new
```

Выходной каталог должен быть пустым. Замените им только сгенерированный `site/`; не копируйте `.data`, окружение и ключи. Сохраните и отправьте изменения обычным commit/push. Проверьте завершение Actions → Publish SMS journal / pages build and deployment.

Онлайн-карточки накладываются на временную базу только в процессе публикации и сборки отчётов; пользовательская локальная база не затрагивается. Для правок материалов опубликованного журнала агентом обновляйте `online-journal.json`, увеличивая `revision` изменённых карточек. `events.json` сохраняет первоначальные источники и данные для первого локального запуска.

Для диагностики сборки откройте https://github.com/juliashar3-debug/newrepository/actions/workflows/build-online-report.yml. Ошибка прав записи требует разрешённых GitHub Actions и доступа `contents: write` для workflow. Не встраивайте токены в код сайта.
